# Study checkpoint 1 — verification and limitations

## Release scope

261 accepted original questions (206 MC,55 SATA), with all stem, clue, objective, overall rationale, option IDs, option wording, keys, option explanations and difficulty reasons checked against their exact accepted candidate objects. Accepted metadata overlays are retained in private provenance outside the repository. All261 public revisions were recomputed. First260 source projections match the audited mapping; the final four newborn-glucose references were compared with their accepted sources directly. No pending or deferred drafts enter the checkpoint.

This is **AI-assisted review**, not independent nursing-educator approval or clinical certification. Difficulty is estimated; coverage is uneven. Hard-only80 is disabled. Use course materials and current clinical policy to resolve questions; this site is an educational aid, not a source of patient-specific care orders.

## Automated checks

- Original20 engine/content tests and TypeScript check remain in the release gate.
- Checkpoint14 tests cover exact bank totals/revisions/fields, MC/SATA key identity,20,000 seeded shuffle draws, unanswered/submitted resume, locking, malformed/foreign imports,200 simulated topic sessions, focus/spacing/family exclusions/exhaustion, track-specific difficulty, session preservation, conflict-notice focus, quota fallback and no-lock storage events.
- All261 public clinical projections were independently compared to accepted candidate hashes by the coordinator, separate from the projection script.
- Public HTML/bank scans reject local filesystem paths, raw private review fields and unsafe reference URL schemes. The checkpoint has no third-party runtime dependencies, analytics, external fonts or remote scripts.
- The original committed/live root HTML, current bank and legacy bank hashes are preserved. The original source build is validated, but its regenerated HTML is not deployed for this checkpoint-only release.

## Browser verification

Disposable Chrome152 profile on macOS, with synthetic progress only. Actual UI checks cover a completed session, MC and SATA, pre-submit rationale withholding, post-submit rationale letters and lock, selection/confidence/order resume, export download, valid restore, rejected malformed/foreign restores, two-tab write protection, corrupt stored-data recovery and explicit no-Web-Locks in-memory fallback. Keyboard Space/Enter interactions and focus transfer are tested. Desktop,390px mobile and200% text-size layouts are inspected for overflow and rendering issues. Original v2/v3 synthetic sentinel values are checked after every workflow; no real learner profile is used.

The independent frozen-code audit found two P2 issues—memory-only tabs blocked by remote storage events and conflict notice focus lost after rerender. Both were fixed, with permanent regression tests and candidate-specific browser reproduction checks before release.

## Not claimed

No Safari/Firefox/Edge or physical-device certification, comprehensive screen-reader audit, full browser-zoom certification, independently calibrated difficulty, validated CAT ability estimate, educator endorsement, hard-only blueprint feasibility, cloud sync, account recovery or old-progress migration. Repeated question families do not increase the practice difficulty estimate. Readiness and pass probability are not inferred. HTTPS hosting necessarily exposes the educational question bank; this is not a secure graded-exam system.

The deployment must pass GitHub's checked workflow and the published checkpoint/root artifact hashes must match the tested outputs. Keep the original root link and prior commit as fallback. The public release manifest reports the frozen bank and preserved-original hashes; subsequent edits require explicit version/history handling.
